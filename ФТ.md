# ФТ: Приложение записи звука с выбором частотного диапазона

Рабочее название: **Sift**

## 1. Суть

Android-приложение записывает звук с микрофона, показывает спектр в реальном времени, позволяет выделить нужный частотный диапазон (одна полоса или несколько), применить полосовой фильтр (band-pass) и сохранить результат — либо как отдельный отфильтрованный файл, либо переписать оригинал.

Юзкейсы: вычленить голос из шумной записи, отфильтровать гул/писк оборудования, оставить только нужный диапазон для диагностики звука (техника, животные, музыкальные инструменты).

## 2. Функциональные требования

### 2.1 Запись
- Запись с микрофона в PCM 16-bit, частота дискретизации 44.1/48 кГц (выбор в настройках).
- Индикатор уровня сигнала (VU-meter) во время записи.
- Пауза/возобновление записи.
- Максимальная длина записи ограничена только свободным местом; предупреждение при < 100 МБ.

### 2.2 Визуализация спектра
- Спектрограмма (waterfall) в реальном времени поверх записи — FFT окно 1024–4096 сэмплов, настраиваемое.
- Отдельно — усреднённый спектр (частота → амплитуда) для удобства выбора диапазона после записи.
- Ось X — частота (лог или линейная шкала, переключатель), ось Y — время (для waterfall) или амплитуда (для среднего спектра).

### 2.3 Выбор диапазона
- После записи (или во время, если фильтрация live) — перетаскиваемые маркеры нижней/верхней границы прямо на спектрограмме.
- Возможность добавить несколько непересекающихся полос (multi-band selection), результат — объединение (OR) выбранных диапазонов.
- Preset-кнопки для типовых диапазонов: голос (300–3400 Гц), бас (20–250 Гц), полный спектр (сброс).
- Прослушивание в реальном времени с применённым фильтром (переключатель "до/после") перед сохранением.

### 2.4 Фильтрация
- Band-pass фильтр (Butterworth, порядок настраивается 2–8) применяется офлайн к WAV-буферу через FFT: forward FFT → зануление бинов вне диапазона(ов) → inverse FFT. Порядок IIR не нужен, т.к. обработка не realtime-стриминговая (фильтрация после записи).
- Для live-прослушивания "до/после" — более лёгкий IIR band-pass (Biquad), т.к. FFT-round-trip на буфер целиком не подходит для потоковой обработки с низкой задержкой.

### 2.5 Сохранение и экспорт
- Сохранение в WAV (без потерь, обязательно) и опционально MP3/AAC (через встроенный кодек Android MediaCodec).
- Метаданные записи: дата, длительность, применённый диапазон(ы) — хранятся в локальной БД, не только в файле.
- Экспорт через системный Share Sheet (Intent.ACTION_SEND) — в мессенджеры, облако, по email.
- Библиотека записей: список, поиск по дате/названию, переименование, удаление.

### 2.6 Не входит в MVP
- Шумоподавление (denoise, spectral subtraction) — отдельная фича, не путать с band-pass.
- Синхронная многоканальная запись (стерео — да, больше каналов — нет).
- Облачная синхронизация.

## 3. Технический стек

- Kotlin, Jetpack Compose, Clean Architecture, MVI, Koin — по стандартному стеку.
- Запись: `AudioRecord` (не `MediaRecorder` — нужен сырой PCM-поток для FFT и фильтрации).
- FFT: своя реализация или `JTransforms`/аналог через JNI, либо чистый Kotlin для MVP (радикс-2 FFT, размер буфера — степень двойки).
- Спектрограмма: кастомный Canvas/Compose Canvas, рендер через `drawImage` с battched bitmap, не перерисовывать полный спектр на каждый кадр — только новую полосу waterfall.
- Хранение записей: файлы в app-specific storage (`getExternalFilesDir`), метаданные — Room (SQLite).
- Экспорт в MP3/AAC: `MediaCodec` + `MediaMuxer`.

## 4. Технические риски / открытые вопросы

- Производительность real-time FFT на слабых устройствах при большом окне (4096+) — нужен профилинг, возможно вынести в отдельный поток с `ExecutorService` и backpressure на буфер.
- Задержка live-прослушивания "до/после" при использовании AudioRecord+AudioTrack в связке — держать буфер маленьким (низкая задержка) ценой качества FFT для live-режима; для сохранения использовать оффлайн-обработку с большим окном.
- Разрешение `RECORD_AUDIO` + поведение на Android 12+ (foreground service индикатор записи).

## 5. Нефункциональные требования

- Работа в фоне при активной записи — foreground service с уведомлением.
- Минимальная версия Android: API 26 (для стабильного `AudioRecord`+`MediaCodec` API).
- Тёмная тема по умолчанию (частотные приложения обычно используются в темноте/студийных условиях).
